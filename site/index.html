How it works

From zero to paper-trading in three commands.

No exchange account, no API-key application forms. A wallet you control, a market you pick, and a switch you flip.

1

Make a wallet 👛

Generate a fresh wallet locally. The private key goes into a git-ignored .env — it never touches the internet.

$ polybot generate-wallet
2

Pick a market 🎯

Browse the most-traded Polymarket markets and get a ready-to-paste config block — token ids included.

$ polybot list-markets -q "election"
3

Flip it on 🚀

Turn the long bot, the short bot, or both on — from a second terminal, while the loop is running. No restarts.

$ polybot on my-market both && polybot run
Signal system

Five indicators built in. Yours plugs in.

Every tick, the signal says LONG, SHORT, or FLAT. Bots enter when it points their way — and exit automatically when it flips away.

🎚️

Threshold

type: threshold

YES price above your upper bound → LONG. Below the lower → SHORT. Dead simple, surprisingly useful.

📈

Moving average

type: moving_average

Fast MA crosses the slow MA → follow the trend. The classic crossover, on prediction markets.

⚡

Momentum

type: momentum

Price moved more than your threshold over the lookback window? Ride it — up means LONG, down means SHORT.

🌀

RSI

type: rsi

Oversold → LONG, overbought → SHORT. Mean-reversion by default, momentum mode if you flip it.

🕹️

Manual

type: manual

You are the indicator. Set LONG, SHORT, or FLAT in config and watch the bots obey. Perfect for testing.

    Safety first
    
Built to not lose your money by accident.

    
Automated trading is risky enough on purpose. Polybot removes the by-accident part.

  

  

    

      🧪
      
Dry-run by default

      
Fresh installs paper-trade. Real prices, real signals, zero real orders — until you set POLYBOT_DRY_RUN=false and fund the wallet. Two deliberate steps, no surprises.

    

    

      🔑
      
Keys stay local

      
Your private key lives in a git-ignored .env file, read only at runtime. Never committed, never uploaded, never asked for by anyone.

    

    

      🛑
      
One-command kill switch

      
polybot kill flips every bot off instantly — from any terminal, while the loop is running. Panic has a button.

    

    

      🧰
      
Tested fully offline

      
The whole test suite runs against a fake exchange: no keys, no network, no orders. You can verify behavior before anything real is at stake.

    

  






  

    FAQ
    
Fair questions.

    
The honest answers, before you flip anything on.

  

  

    

      Will this spend real money the moment I run it?
      
No. Polybot starts in DRY-RUN (paper) mode: it runs the full loop, logs exactly what it would do, and places no real orders. Live trading requires you to both set POLYBOT_DRY_RUN=false and fund the wallet with USDC on Polygon.

    

    

      Where does my private key live?
      
In a local .env file that is git-ignored. You generate the key yourself with polybot generate-wallet (or paste in your own). The bot reads it only at runtime — never paste it into a chat, issue, or commit.

    

    

      Can I add my own indicator?
      
Yes — that's the whole point of the signal system. Write a class with one evaluate(ctx) → LONG/SHORT/FLAT method, register it in one line, and reference it from config.yaml. The built-in indicators are examples to copy from.

    

    

      Do the bots exit positions too?
      
Yes. When the signal flips away from a side, the bot sells the shares it bought — long and short bots both enter and exit automatically. Turning a bot off stops new entries.

    

    

      Is any of this a profitable strategy?
      
No promises — the built-in signals are demos, not alpha. Prediction markets can go to zero, and you should only trade what you can afford to lose. Start in dry-run, stay skeptical.
